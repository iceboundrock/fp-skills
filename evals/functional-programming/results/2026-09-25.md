## Why this run

The PR #19 skill treated `Result`, `Option`, `Either`, dependency records,
and `pipe`/`compose` as red flags by name. Scenario H was added to show the
cost of that: a case where a small generic `Result<T, E>` with `flatMap` is
the smallest construct that states the contract, and where the lr skill
talks agents out of it.

### First version of the H prompt

between steps. All four RED runs (none ×2, lr ×2) produced a shared result
union with early returns, and all four had a fair reason: the awaits sit

## Post-review: A clock reads

PR review pointed out that both A runs replaced two `Date.now()` reads with
one, named it as a behavior change, and were still graded pass against a
rubric that says effects stay "in the same order" and the skill's "preserve
behavior" step. The first response was to accept a disclosed single sample
and fail a silent one, on the model of the input-mutation rule in the
rubric's Neutral list.

A second review rejected that: disclosure does not make the change
behavior-preserving. At an hour boundary the original code can grant the
discount in one hour and stamp `placedAt` in the next, one sample changes
that observable result, and the task asked for a refactor and tests, not
that change. The rubric now requires both reads ("read once for the
happy-hour check and again for `placedAt`, as before"), lists the collapse
as a fail signal whether or not the answer says so, and drops the Neutral
bullet. Both GREEN A runs are regraded as fail; the quotes under "A" above
are where each run made the change.
