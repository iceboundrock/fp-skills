## Baseline failures and rationalizations (verbatim)

**A, old skill.** Pure pricing extracted correctly, but it also added
`Clock`, `OrderStore`, `Analytics`, a `PlaceOrderDeps` record, and a
`defaultDeps` parameter, and rewrote the loop as `reduce`. The shell test
still used `vi.fn` fakes.
> "Time, persistence, and analytics are injected via a PlaceOrderDeps record
> (Clock, OrderStore, Analytics), so side effects are visible at the call site"

**C, no skill (run 1).** Kept Spring, but added a hand-rolled `Either<L, R>`
with `fold` and an `Optional.map(...).orElseGet(...)` chain in place of two
`if`s.
> "no functional/vavr-style library on the classpath, so I hand-rolled a
> minimal Either type"
> "No reassigned variables / early returns"

**D, no skill.** Run 1: `functools.reduce` copying the dict on every event.
Run 2: copied the generator into a list to allow two passes.
> "'More functional' means: no local mutable state (...), a pure accumulation
> step, and using functools.reduce as the fold in place of the imperative for
> loop."
> "no manual loop, no mutable accumulator dict, no sentinel-checking
> `if x is None` mutation pattern"

**D, old skill.** `reduce` over a frozen accumulator dataclass, then
`MappingProxyType`, and changed the public `Summary.counts` type from `dict`
to `Mapping`.

**F, no skill.** Turned `DbUpdateException` into a `PersistenceFailure`
result case. Claimed a private constructor makes C# `switch` exhaustive and
promoted CS8509 to an error, which would break the build.
> "Infra failures are now a domain outcome too, not a leaked exception."

**F, old skill.** Generic `Result<TValue, TError>` plus `Unit`, rewrote the
`Account` entity as an immutable record, wrapped `DbUpdateException`, and made
the same CS8509 claim.
> "the two-case Result makes ... explicit in the type, which is the stronger
> guardrail."

**G, no skill.** Added a fourth subclass and turned the factory into a dict
of classes. Never considered plain functions.

## REFACTOR iterations

| Version | Change | Trigger |
|---|---|---|
| v2 | Decision function must be reachable from tests; the exhaustiveness row names the languages that check it | C v1 made the decision `private static`; F v1 still claimed C# exhaustiveness |
| v3 | Stated that promoting CS8509 to an error breaks the build | F v2 offered `WarningsAsErrors CS8509` as an alternative |
| v4 | Replaced the prohibition with a recipe: a `Match` method with one delegate per case | F v3 run 1 set `CS8509.severity = error` while quoting the skill's own caution |

The v4 change follows writing-skills' "match the form to the failure": the
agent wanted build-time enforcement and would negotiate with any "don't",
so the fix is a positive recipe. A later wording-only change (the red-flag
bullet now says "hand-rolled") was not re-run.
